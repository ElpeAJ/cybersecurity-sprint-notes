# Day 21: Cryptography Fundamentals & Algorithms

## Cryptographic Principles
* **Definition:** Cryptography is the practice of securing digital information by converting readable plaintext into unreadable ciphertext. This ensures data properties remain protected both while traveling across an untrusted network environment (Data in Transit) and while stored statically on local host drives or database repositories (Data at Rest).
* **The Shared Objective:** Maps directly to the **Confidentiality** and **Integrity** pillars of the core security framework, ensuring unauthorized third parties cannot spy on or alter system information vectors without detection.
* **Plaintext:** Raw, unencrypted, and human-readable information vectors before processing.
* **Ciphertext:** Scrambled, unreadable data structures generated by processing plaintext through a cryptographic algorithm using an explicit key.

## Symmetric vs. Asymmetric Encryption Architectures

Encryption is a **two-way, reversible process** used when data must be securely scrambled for transport or storage and later decoded back into its original text state using an explicit mathematical key.

| Technical Parameter | Symmetric Encryption Matrix | Asymmetric Encryption Matrix |
| :--- | :--- | :--- |
| **Key Architecture** | Utilizes **one single shared key** for both locking (encrypting) and unlocking (decrypting) operations. | Utilizes a mathematically linked **Public and Private Key Pair**. Data locked with the public key can only be unlocked by the private key. |
| **Operational Speed** | High performance; exceptionally fast and computationally lightweight. | Slower; highly resource-intensive and computationally expensive. |
| **Primary Use Case** | Bulk data encryption, bulk storage protection, and long-term file encryption blocks. | Initial secure connection handshakes, identity verification, and digital signatures. |
| **Core Limitation** | **The Key Sharing Problem:** Both sides must securely exchange the single key beforehand without an eavesdropper intercepting it. | Vulnerable to key management loss; if the private key is exposed or dropped, all encryption layers fail instantly. |
| **System Resolution** | Requires a pre-shared secure secondary path to distribute the primary master key string. | Solves the key sharing dilemma completely because the public key can be freely distributed to anyone on the internet. |

> 🌐 **Hybrid System Integration Note:** Modern architectures (such as **HTTPS / TLS**) do not choose one over the other. They use both together: **Asymmetric Encryption** securely executes the initial connection handshake to verify identity and share a temporary key, and **Symmetric Encryption** instantly takes over to handle the fast, bulk transmission of data throughout the rest of the session.

## Hashing: The One-Way Function

### Foundational Concept
Unlike encryption, **hashing is a strict one-way, irreversible mathematical operation**. It takes an input string of any size and converts it into a scrambled, fixed-length alphanumeric output text block (a hash value or message digest). 

### The Blender Analogy
Putting data into a hashing algorithm is analogous to processing an apple inside a mechanical blender. You obtain a blended smoothie output (the hash), but it is physically impossible to reverse the process to reconstruct the original intact apple from the liquid state.

### Primary Structural Use Cases
* **Secure Password Storage:** Systems hash your password locally and save only the resulting string in the database. When logging in, the system hashes your input and checks if the outputs match. This ensures that if the database is leaked, the attacker only steals one-way hashes rather than cleartext user credentials.
* **File Integrity Verification:** Software developers publish hash values alongside installation downloads. Users hash their downloaded files locally; if the alphanumeric strings match perfectly, it proves the file has not been altered or injected with malware.

## Symmetric Encryption Architecture & Algorithm Analysis

### Foundational Concept
Symmetric encryption utilizes **one single shared key** for both the locking (encryption) and unlocking (decryption) operations. It operates like a physical mechanical padlock where the exact same key closes the shackle and opens it again; both the sender and the receiver must possess an identical duplicate copy of that secret key.

### Core Metrics Evaluation
* **Strengths:** Exceptionally fast and mathematically efficient. It demands very low computational resource overhead, making it perfectly suited for encrypting large volumes of bulk data or drive storage containers.
* **The Key Distribution Problem:** This is the primary structural limitation of symmetric architectures. Both communication parties must somehow exchange the single secret key securely before any encrypted traffic can pass. If an eavesdropper intercepts or steals the key string during this initial distribution phase, the entire security layer breaks down instantly.

### 🛠️ Profile: Symmetric Block and Stream Ciphers
* **Advanced Encryption Standard (AES):** One of the most secure, bulletproof symmetric algorithms in service today. It generates highly robust variable key choices including **128-bit, 192-bit, and 256-bit** structures. Cryptographic keys of this scale are totally immune to brute-force guessing; it is estimated that attempting to crack a single AES 128-bit key would require modern supercomputers billions of years.
* **Triple DES (3DES):** A historic block cipher that builds upon the original 1970s Data Encryption Standard (DES) framework. The original DES generated 64-bit keys, but only utilized 56 active bits for encryption, making it small and easily breakable by modern compute clusters. 3DES escalates protection by applying the legacy DES algorithm three consecutive times using three independent 56-bit keys, yielding an effective key length of **168 bits**. While still used for legacy backwards compatibility, organizations are actively deprecating 3DES due to blocks restrictions and performance limits.
* **ChaCha20:** A specialized, high-performance symmetric encryption engine designed to securely encode streaming data blocks rapidly.
* **Lab Practice Context:** Simulated using online string manipulation platforms at **`encode-decode.com`**. *Critical Analyst Observation:* Processing the exact same plaintext string multiple times using the same algorithm but changing the key value produces completely unique ciphertext strings. This proves that system security relies entirely on the secrecy of the key, not the secrecy of the math.

## ⚙️ Asymmetric Encryption Architecture (Public-Key Cryptography)

### Foundational Concept
Asymmetric encryption solves the key distribution problem completely by utilizing a mathematically linked **Public and Private Key Pair**. What one key locks, only the opposing key in that specific pair can unlock.
* **The Public Key:** Shared openly and freely with anyone in the world on the internet. It can only lock (encrypt) data, not decrypt it.
* **The Private Key:** Kept strictly secret and never shared under any circumstances; it remains guarded by its individual owner.

### The Open Mailbox Analogy
Asymmetric public keys function like a secure, open mailbox mounted on a street post. Anyone walking past can drop a secret letter through the slot and snap the container shut (Public Key Encryption). However, once the door clicks closed, no one standing on the street can reach back inside to read the letters. Only the mailbox owner holding the private master key can unlock the box to extract and read the contents (Private Key Decryption).

### Core Metrics Evaluation
* **Strengths:** Eradicates the key exchange crisis. If a sender wants to transmit a confidential payload, they simply query the receiver's public key, encrypt the file, and send it. Even if an attacker captures the file and public key mid-transit, they cannot read it because only the recipient's private key can decrypt it. This also enables **Digital Signatures**, where a user encrypts a hash with their private key, allowing anyone holding their public key to verify the message's origin and integrity.
* **Weaknesses:** Exceptionally slow and computationally heavy compared to symmetric alternatives. The underlying mathematics—such as factoring massive prime numbers or tracking complex curves—imposes severe processing latency, making it completely impractical for encrypting large files directly.

### 🛠️ Profile: Asymmetric Algorithms
* **Rivest Shamir Adleman (RSA):** Named after its three MIT creators, RSA was one of the earliest public-private key pair systems deployed. Because it generates a double key pair from complex prime number scaling, it requires massive key sizes to remain secure. RSA key scales default to **1,024-bit, 2,048-bit, or 4,096-bit** configurations, and are reserved for protecting highly sensitive handshake layers or identity exchanges.
* **Digital Signature Algorithm (DSA):** Introduced by NIST in the early 1990s as a standard asymmetric engine. Generating standard key sizes of **2,048 bits**, DSA is widely implemented across modern Public Key Infrastructure (PKI) frameworks to complement RSA by handling cryptographic authentication signatures.
