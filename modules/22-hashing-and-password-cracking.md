# Day 22: TLS, PKI, & Cryptographic Weaknesses

## Transport Layer Security (TLS) & Public Key Infrastructure (PKI)
* **Transport Layer Security (TLS):** Operating at **Layer 4 (Transport Layer) of the OSI model**, TLS provides an encrypted communication tunnel between a client browser and a remote server. It enforces **Confidentiality** and **Integrity** across the network wire.
* **Historical Context:** **Secure Sockets Layer (SSL)** is the legacy predecessor to TLS. SSL is completely obsolete and deprecated for enterprise production settings due to design vulnerabilities. Modern environments deploy **TLS 1.2 and TLS 1.3**.
* **The Padlock Icon:** The padlock displayed inside a browser address bar confirms that TLS encryption is active.
>*Crucial Analytical Insight: HTTPS only guarantees that data is encrypted in transit. It does not guarantee that the destination website itself is safe, trustworthy, or legitimate.*
* **Public Key Infrastructure (PKI):** The complete framework of trusted organizations, governance rules, and technologies established to issue, manage, distribute, and verify digital identity certificates.

---

## Digital Certificates & Verification Process
A **Digital Certificate** functions as the verifiable digital identity card for a web asset. It binds a public cryptographic key to an organization's domain name, verified and cryptographically signed by an authoritative body called a **Certificate Authority (CA)**.

### Core Components of a Certificate
1. **Target Domain/Website:** The matching alphanumeric address of the server node.
2. **Public Key Asset:** The asymmetric key block used by clients to encrypt session handshakes.
3. **Issuer:** The trusted authorizing body (Certificate Authority) that validated the entity.
4. **Validation Period:** Explicit calendar start and expiration timestamps.
5. **Digital Signature:** The cryptographic seal generated by the CA's private key to prevent tampering.

### Step-by-Step Browser Verification Process
1. The browser initiates a connection and receives the website’s digital certificate.
2. The browser references its internal root store to verify the certificate was signed by a globally trusted Certificate Authority.
3. The browser checks that the current calendar timestamp falls within the validation period boundaries and confirms the certificate's domain matches the actual URL requested.
4. **Failure State:** If any structural step fails (expired window, unmapped domain, or untrusted issuer), the browser halts the connection and throws an invalid certificate warning block.

---

## 📌 Advanced Defense: Certificate Pinning
* **The Core Mechanism:** Certificate Pinning bypasses standard broad CA trust logic. An application or browser client is explicitly configured to trust **only one specific, hardcoded cryptographic key or certificate fingerprint** for a designated service, instead of trusting any valid certificate signed by any generic trusted CA.
* **The Threat Mitigation Target:** Specifically engineered to neutralize sophisticated **Man-in-the-Middle (MitM) attacks**. 
* **Operational Reality:** If an attacker compromises a rogue or weak Certificate Authority to generate a fraudulent but technically "valid" certificate for a domain, a pinned application will intercept the traffic, detect that the certificate fingerprint does not match the hardcoded value, and drop the connection instantly.

## ❌ Cryptographic Weaknesses & Broken Primitives

### 1. Message Digest Algorithm 5 (MD5)
* **Definitional Profile:** An early cryptographic hashing function that generates a fixed-length **32-character hexadecimal string** output digest.
* **Current Assessment Status:** **Totally Broken and Insecure**. Because MD5 is computationally fast, it allows attackers to build massive precomputed dictionaries. Furthermore, it suffers from severe **Collision Vulnerabilities**, meaning different plaintext inputs can produce matching hash digests.

### 2. Unsalted Hashes
* **The Threat:** Storing a password hash without a unique modifier means the identical plaintext input string will always yield the exact same alphanumeric hash string globally.
* **The Exploit Vector:** Attackers use precomputed **Rainbow Tables** — massive databases matching common passwords to their pre-calculated hash values—to reverse-engineer and crack unsalted databases almost instantly without brute-forcing the keys manually.
* **The Remediation (Salting):** Appending a unique, random string of characters onto a password before processing it through the hashing engine. This ensures that if two users choose the identical password string (`123456`), their stored database outputs look completely distinct, neutralizing rainbow tables entirely.

### Comparison of hashes (The Avalanche Effect)
Altering a single character's capitalization from uppercase `H` to lowercase `h` causes the output signature strings to look completely non-matching, changing the alphanumeric character sequence entirely. This behavior validates the **Avalanche Effect**. It demonstrates why hashing functions are exceptionally secure for verifying data integrity: if an attacker modifies even a single bit of a document during transit, the resulting digest output shifts completely, exposing the tampering attempt.
